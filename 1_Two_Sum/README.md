# 1. Two Sum ( Легкая, 2 балла)

## Идея решения
Подход решения "в лоб" подразумевает полный перебор всех пар чисел, что дает квадратичную сложность $O(N^2)$. По условию желательно найти алгоритм быстрее, чем за $O(N^2)$, то есть нам нужно избежать полного квадратичного перебора (двух вложенных циклов). Нам нужен способ пройти по массиву максимум один раз.

Суть задачи — искать пары чисел, которые в сумме дают искомое число (`target`). Мы можем пойти от обратного: для только что рассмотренного числа сразу искать его "число-пару", которое равно `target - current_number`. 

Чтобы это сработало, нам нужно запоминать уже рассмотренные числа и их изначальные индексы (так как в ответе требуются именно индексы). Идеальной структурой данных для этого выступает HashMap (`std::unordered_map`). Сам массив не отсортирован, сортировать его нельзя (потеряем индексы), а хэш-таблица дает возможность искать "число-пару" без перебора.

Алгоритм:
1. Идем по массиву.
2. Проверяем, есть ли "число-напарник" в хэш-таблице.
3. Если есть — мы нашли ответ, возвращаем индексы.
4. Если нет — сохраняем текущее число как ключ, а его индекс как значение, чтобы оно могло стать напарником для последующих чисел.

## Оценка сложности (Complexity)
- **Время:** $O(N)$.
  Мы проходим по массиву ровно один раз. Время поиска нужного числа в хэш-таблице в среднем занимает константное время $O(1)$. 
- **Память:** $O(N)$
  Для хэш-таблицы потребуется дополнительная память. В худшем случае (если нужные числа стоят в самом конце массива), нам придется сохранить в хэш-таблицу $N-1$ элементов.
