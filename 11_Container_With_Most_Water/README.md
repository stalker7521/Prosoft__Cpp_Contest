# 3. Container With Most Water (Средняя, 6 баллов)

**Ссылка:** [LeetCode: Container With Most Water](https://leetcode.com/problems/container-with-most-water/)

## Идея решения
Решение "в лоб" подразумевает проверку каждой возможной пары линий с помощью двух вложенных циклов. Это дает квадратичную сложность $O(N^2)$, что не пройдет по времени при размере массива в 10^5 элементов.

Оптимальное решение использует паттерн **Two Pointers (Два указателя)**. 
Мы расставляем указатели по краям массива (`left` в начало, `right` в конец), получая максимально возможную ширину контейнера. Объем воды всегда ограничен высотой *меньшей* линии. 

Главное правило сдвига указателей: нет смысла двигать указатель, стоящий на большей высоте. Если мы его сдвинем,то ширина контейнера уменьшится, а высота всё равно останется ограничена той линией, которая ниже, то есть площадь гарантированно станет меньше.
Единственный шанс найти большую площадь - это двигать тот указатель, который указывает на **меньшую** высоту, чтобы постараться встретить линию повыше.

## Алгоритм
1. Инициализируем "указатели" и переменную для хранения площади.
2. Выполняем цикл, который будет работать пока указатели не окажутся рядом друг с другом:
   * Высчитываем текущую площадь: `ширина * высота_меньшей_линии`.
   * Обновляем максимальную площадь, если текущая площадь больше.
   * Сравниваем высоту указателей. Указатель с меньшим значением сдвигаем навстречу другому.
3. Возвращаем максимальную площадь.

## Оценка сложности
* **Время: $O(N)$.** Мы проходим по массиву всего один раз. Каждый элемент посещается максимум один раз.
* **Память: $O(1)$.** Алгоритм требует хранения нескольких переменных для хранения индексов и текущей площади. Доп.память не зависит от размера массива.
